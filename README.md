# merge-openapi-files

> Demo repository: merge several OpenAPI spec files into a single spec file using **Redocly CLI**, triggered automatically when a Pull Request is approved.

---

## Repository structure

```
merge-openapi-files/
├── .github/
│   └── workflows/
│       └── merge-oas.yml      # GitHub Actions workflow
├── oas-inputs/                # Source OpenAPI spec files (one per domain)
│   ├── users-api.yaml
│   └── orders-api.yaml
├── oas-merged/                # Output – generated by the workflow
│   └── merged-openapi.yaml    # ← produced automatically, do not edit by hand
├── .gitignore
└── README.md
```

---

## How it works

1. Developers add or modify YAML spec files inside **`oas-inputs/`** on a feature branch.
2. They open a **Pull Request** to `main`.
3. A reviewer approves the PR.
4. The `pull_request_review` GitHub event fires and the **merge-oas** workflow runs automatically.
5. The workflow uses **`redocly join`** to merge all files in `oas-inputs/` into a single `oas-merged/merged-openapi.yaml`.
6. The merged file is committed back to the PR branch and also uploaded as a **workflow artifact**.

## GitHub Actions runners

### What is a runner?

A runner is the **compute environment** that executes the steps defined in the workflow. You never have to start it manually — GitHub manages it.

### Option A — GitHub-hosted runners (used by this demo) ✅

This repo uses `runs-on: ubuntu-latest`, which means GitHub automatically provisions a **fresh Ubuntu VM** for every workflow run. There is nothing to install or start on your side.

| What you need to do | Nothing — GitHub handles it |
|---|---|
| Cost | Free for public repos; included minutes for private repos |
| Maintenance | None |

**How the workflow is triggered:**

```
feature-branch  →  open PR  →  reviewer clicks "Approve"
                                        │
                               pull_request_review event
                                        │
                               GitHub allocates ubuntu-latest runner
                                        │
                               merge-oas job runs
                                        │
                               merged-openapi.yaml committed to PR branch
```

To watch a run: **GitHub repo → Actions tab → "Merge OpenAPI Specs"**

---

### Option B — Self-hosted runner (if you need your own machine)

Use this if you have network restrictions, need specific tools pre-installed, or want to use your own hardware.

#### 1. Register the runner

Go to: **GitHub repo → Settings → Actions → Runners → New self-hosted runner**

Follow the commands shown (example for macOS/Linux):

```bash
# Create a dedicated directory
mkdir ~/actions-runner && cd ~/actions-runner

# Download the runner package (version shown in GitHub UI)
curl -o actions-runner.tar.gz -L \
  https://github.com/actions/runner/releases/download/v2.x.x/actions-runner-osx-x64-2.x.x.tar.gz

# Extract
tar xzf actions-runner.tar.gz

# Configure (token and URL are shown in the GitHub UI)
./config.sh --url https://github.com/<owner>/merge-openapi-files \
            --token <REGISTRATION_TOKEN>

# Run the runner (interactive – keeps it alive in the terminal)
./run.sh
```

#### 2. Install as a background service (macOS)

```bash
# Install and start as a launchd service (survives reboots)
sudo ./svc.sh install
sudo ./svc.sh start

# Check status
sudo ./svc.sh status

# Stop / uninstall
sudo ./svc.sh stop
sudo ./svc.sh uninstall
```

#### 3. Update the workflow

Change `runs-on` in `.github/workflows/merge-oas.yml`:

```yaml
# Before (GitHub-hosted)
runs-on: ubuntu-latest

# After (self-hosted)
runs-on: self-hosted
```

### Option C — Run locally with `act` (for testing without pushing)

[`act`](https://github.com/nektos/act) lets you run GitHub Actions workflows locally inside Docker.

```bash
# Install (macOS)
brew install act

# Simulate a pull_request_review approval event
act pull_request_review \
  -e .github/test-events/pr-approved.json \
  --secret GITHUB_TOKEN=$(gh auth token)
```

Create the test event payload at `.github/test-events/pr-approved.json`:

```json
{
  "action": "submitted",
  "review": { "state": "approved" },
  "pull_request": {
    "head": { "ref": "feature/my-branch" }
  }
}
```

## Adding a new API spec

1. Create a new file in `oas-inputs/`, e.g. `products-api.yaml`.
2. Make sure every `operationId` is unique across all files (Redocly will warn if not).
3. Open a PR — the workflow runs automatically on approval.
